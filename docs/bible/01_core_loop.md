# 01 核心循环

## 定义（≤ 100 字）

玩家在限定球数内通过瞄准和蓄力发射小球，观看它在图钉阵中弹跳并试图落入袋洞得分；每进一袋保一球、得一奖，球数耗尽即回合结束、结算总分后玩家可选择重开，循环往复。

## 循环图

```
瞄准 → 蓄力 → 发射 → 看球弹 → 看进袋洞 → 看球数变化 → 想再来一发 → (回到瞄准)
```

## 阶段拆解

| 阶段 | 玩家动作 | 系统响应 | 当前状态 |
| --- | --- | --- | --- |
| 瞄准 | 鼠标位置决定方向（±80° 钳制） | —（预览线规划中） | ✅ 已实现（`launcher.gd`） |
| 蓄力 | 按住积累能量（3s 蓄满） | 蓄力条实时反馈（蓄满变绿） | ✅ 已实现 |
| 发射 | 松开按键 | 按蓄力值施加冲量、生成球、扣库存 | ✅ 已实现 |
| 看球弹 | 观察 | 图钉物理反弹 + 墙体反弹 | ✅ 已实现 |
| 看进袋洞 | 观察 | 进袋 +3、球销毁 | ✅ 已实现 |
| 看球数变化 | 观察 | HUD 库存实时刷新；≥60 过关 / 归零结算 | ✅ 已实现 |
| 想再来一发 | 过关自动续局 / 失败点重试 | 清场 + 重置 | ✅ 已实现 |

## 核心循环的不可妥协点

1. 从"瞄准"到"想再来一发"必须形成闭环——任何一段断掉，游戏就不再是 pachinko roguelike。
2. 玩家必须能在"发射前"做出有意义的决策（方向 + 力度），否则只是看随机数。
3. "想再来一发"必须由 **变化的结果** 驱动（分数变了 / 得到升级 / 刷新纪录）。

## 与 MVP 的关系

见 `../MVP_Scope.md`。MVP 只覆盖"瞄准 → 蓄力 → 发射 → 看球弹 → 进袋 → 球数 → 重开"这条最短闭环。
